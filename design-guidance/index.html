Behaviour

Interaction Patterns

Motion, hover, focus, and loading states.

Motion & transitions
ContextDuration / easingNotes
AB hover bginstant / noneSnap — no transition on simple hovers
AB toggle (switch)0.15s easeThumb slide only
AM hover bg0.15s easeBackground opacity fade
AM modal open0.2s ease-outTranslate Y + opacity
AM backdrop blurCSS backdrop-filterApplied statically; no animate
✓ Do

Use transition: background 0.15s ease for AM interactive elements.

Keep AB transitions at zero or minimal — it's a utility-first app.

Use CSS backdrop-filter: blur() for AM glass surfaces.

✗ Don't

Don't animate colour changes on AB — it feels sluggish on data-dense views.

Don't skip focus rings — both apps must be keyboard accessible.

Don't use backdrop-filter on AB — it's not part of the aesthetic.

§ 08
Checklist

Rules & Checklists

The short list of hard rules every PR touching UI must pass.

✓ Universal DOs BOTH
  1. Scope variables — always use the correct ab-scope / am-scope wrapper.
  2. Dark-only — no light-mode styles. Both apps are permanently dark.
  3. 1 px borders — never thicker unless explicitly noted (e.g. callout left-border = 2 px).
  4. Keyboard access — every interactive element must be reachable and operable by keyboard.
  5. Font inherit — form elements (input, select, button) must set font: inherit.
  6. Text contrast — primary text ≥ 4.5:1, secondary ≥ 3:1 against the surface it sits on.
✗ Universal DON'Ts BOTH
  1. No white backgrounds — ever. Even overlays should use rgba dark.
  2. No inline colour literals — outside of demo swatches, always use CSS vars.
  3. No !important — signals broken specificity; fix the cascade instead.
  4. No placeholder styling as label — placeholders disappear on focus; use real labels.
  5. No cross-app class leakage — .ab-* classes must not appear in AM templates and vice versa.
AB AB-specific rules
  1. Chip taxonomy — use the defined chip classes (.ab-chip-audiobook, .ab-chip-book, etc.). Don't invent new colours without adding a class.
  2. Table layout for lists — the book list is a grid, not flexbox soup. Use .ab-book grid template for all list items.
  3. Summary cards are buttons — they must be <button> elements for keyboard / screen-reader access.
  4. Sort toggle = segmented control — don't replace with a <select> on desktop; the segmented control is intentional.
AM AM-specific rules
  1. Album art is square — enforce aspect-ratio: 1. Never stretch or letter-box.
  2. Storefront chips are positional — their colour is hash-derived from the country code. Never manually assign colours.
  3. Gradient text is brand — only use --am-grad on brand/logo text and primary CTAs. Not on body copy.
  4. Watch state = gold — --am-gold (#f5c842) is reserved exclusively for the watch/tracking feature. Don't reuse it elsewhere.
  5. Sidebar width is fixed — 220 px. Do not make it resizable or collapsible without a deliberate UX decision.
Pre-merge UI checklist BOTH
☐ Scope check
All new classes use the correct ab- / am- prefix, or doc-layer prefix if in this file.
☐ Token check
No raw hex values outside of :root / .ab-scope / .am-scope token definitions.
☐ Dark mode
Checked on a display with proper black levels; no grey bleed.
☐ Keyboard nav
Tab through all interactive elements; focus ring visible.
☐ Responsive
Checked at 1280, 1024, 768 px widths.
☐ No leakage
AB styles don't affect AM views and vice versa.
☐ Font inherit
All form elements render with the correct app font.
